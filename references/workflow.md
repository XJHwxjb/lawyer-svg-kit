# 整片制作：从口播素材到成片（逐步执行指南）

本指南写给执行任务的 Agent。目标是交付用户要求的视频文件，而不仅是方案、代码片段或 10 秒样片。每一阶段都要产生可检查的结果；遇到不能自行判断的关键事实，先完成不依赖该事实的部分，再向用户简洁说明缺少什么。

人物与剧情动作一律走本 Skill 的资产库（[roster.md](roster.md) 查库 → 缺则按 [character-forge.md](character-forge.md) / [action-forge.md](action-forge.md) 造 → [studio.md](studio.md) 预览验收）。**不要使用带五官表情的卡通人物**——无表情极简剪影是用户定稿风格。

## 一、先读懂这次任务

1. 找出用户要的最终结果：完整成片、某一段样片，还是只修改现有视频。用户明确只要样片时，做到样片就交付并等待反馈；要完整视频时，10 秒样片只是内部检查步骤，不能当作完成。
2. 记录素材、输出位置、语言、发布平台、时长、真人画面安排、风格和必须保留的内容。**画幅是项目级单选**：横屏 16:9 或竖屏 9:16，由稿件/平台或律师口头指定；**稿件没写就先问律师选哪一种，问清再开工**，之后分镜、验收、导出、composition 全部只跟随这一个画幅。
3. 检查本机能否读取文件并实际运行所需工具。项目保存在用户指定目录；输入文件只读，复制到新工程处理。未经授权，不把客户音视频、案件材料、人像或证据上传到公开仓库或外部服务。

**这一步应得到：** 素材清单、输出要求（含选定画幅）和可用工具记录；有不能打开的文件时记录具体路径与错误。

## 二、识别输入并建立可靠时间轴

| 已有素材 | 执行方法 | 需要特别注意 |
|---|---|---|
| 口播视频 + SRT | 检查视频与字幕时长；以 SRT 时间为起点，播放并逐句核对。 | 画面和音轨来自同一段连续素材；不要再叠加一份同源音频。 |
| 口播视频 + 无时间文字稿 | 提取原声，用环境中可用的转写/对齐工具建立带时间戳的逐句稿；对照用户稿与实际发言。 | 稿件不一定等于实际口播，不能把文字稿误当作已有准确时间的字幕。 |
| 口播音频 + 头像 + 稿件/SRT | 保留原音频，以头像或经用户许可的形式呈现讲述者；动作画面和字幕按音频时间对齐。 | 静态头像不是会说话的真人视频，不要声称做了口型驱动。 |
| 只有文字稿 | 用户要求成片时，先确认是否允许生成配音、用什么声音；无法取得授权则完成分镜等独立部分并说明缺口。 | 不要自行模仿特定真人的声音。 |

用 `ffprobe` 或同类工具检查时长、分辨率、帧率、旋转信息与音轨；实际试听/观看开头、中间和结尾。SRT 比视频早、晚或不完整时，先检查是否同一版本；有明确证据时调整并记录，仍无法判断的关键差异应询问用户，**不得自行猜测法律事实、案例、价格、金额或统计数字**。用户给了 SRT 不代表它一定正确。

缺少转写工具时可用有权限的本地工具；拟用远程服务前先确认传输哪些素材、传给谁，获得授权后再执行。不能对齐时说明未完成并保留可编辑结果，不要伪称字幕已同步。

时间轴数据用 [scripts/prepare_timing.py](../scripts/prepare_timing.py) 生成（用法见 [remotion.md](remotion.md)）。

**这一步应得到：** 可校对的逐句时间轴，素材时长、音视频状态和未解决差异记录。

## 三、把口播逐句变成分镜

新建 `STORYBOARD.md` 分镜表，对完整口播从头到尾逐段处理，不要只设计开头。

**单一分镜文档规则**：一个工程只允许一份 STORYBOARD.md。不要另建"分栏版/修订版/最终版"副本——改方案就直接改这份文件。后续的 film.config.js（或 Remotion 场景代码）、字幕、验收记录都必须能逐行对应回这份分镜；发现代码与分镜不一致时，以分镜为准修代码，或先改分镜再改代码，不允许两边各说各话。成片命名固定为 `out/<案件名>_<画幅>.mp4`（画幅标签 = 横屏16x9 / 竖屏9x16），合成脚本的输出名必须与之一致。

每行至少包含：

```text
镜头 03 | 00:00:12.000–00:00:16.000 | 原句：……（填用户真实原句）
人物与动作：谁 → 对谁 → 做什么（roster.md 的动作 id）；道具起点 → 接触 → 终点
动画：开始时间 → 关键动作时间 → 停稳时间；镜头从哪个焦点到哪个焦点
画面信息：标签、数字及 revealAt（仅在原稿支持时）；字幕和真人安全区域
下一镜衔接：人物/道具最后位置、朝向、缩放、层级
资源：真实文件路径或组件名；未确认事实与限制
```

把原句变成可见动作：口播说"聊天记录和转账流水都要保存"，可分成"人物在手机上保留聊天记录 → 把转账凭证放入档案夹 → 两类材料并排对应"。这不是证据确实存在或某人一定犯罪的证明。**不要加入原稿没有的涉案金额、身份、地点或结论。** 抽象规则用天平、证据链或对照线辅助（[legal-icons.md](legal-icons.md)），但不能整片只让文字逐条浮现。叙事与节奏方法见 [narrative.md](narrative.md)。

长视频先按主题分段，再细化到逐句或短句组；同一场景内让人物行动、道具、视线或构图随语义变化。核查首句到末句每个时间段都被覆盖，镜头之间没有无意空白、重叠、漏句或字幕被头像遮挡。

**这一步应得到：** 覆盖完整时长的分镜表；不确定事实有标记，未被当作已确定内容写进画面。

## 四、选角与动作准备（资产库）

1. 按分镜列出角色与动作清单，查 [roster.md](roster.md)：角色 → 人物 id + 变体；动作 → 动作 id。业务领域矩阵可直接照抄组合再按稿件微调。
2. 库里没有的角色/动作，按 [character-forge.md](character-forge.md) / [action-forge.md](action-forge.md) 造，造完回写 roster.md。
3. 按 [studio.md](studio.md) 起预览台，在**案件选定的画幅**下逐动作验收：t = 0/.12/.3/.5/.7/.9/1 无异常、控制台零报错、接物方朝向正确、竖屏安全区无剧情元素。
4. 飞行道具给出方 `opt:{noProp:true}`；baked 手持道具不含文字；法条/金额/日期全部替换为稿件值（库内演示默认值仅供预览）。

**这一步应得到：** 案件 cast 表、全部动作在选定画幅验收通过的记录；新造资产已回写 roster.md。真实客户素材不进入 Skill 目录或公开仓库。

## 五、完成整片，不能停在样片

按分镜依次创建覆盖完整口播时长的场景。始终以原声时间为主轴：原视频连同音轨连续播放一次；如需单独处理音频，静音视频中的声音，确保处理后的音轨只播放一次且没有变速或漂移。字幕按起止时间显示；SRT 不要无故改写原句。

**合成路线二选一（SKILL.md §3.5），不要混用：**

- **零依赖管线（默认推荐）**：按 [../pipeline/README.md](../pipeline/README.md) 把模板复制进案件工程，把分镜逐行翻译成 `film.config.js` 的 shots（每镜头的 dur/act/bg/camera/focus），`node render.cjs` 逐帧渲染（内置交叉淡化与镜头运动），`bash compose.sh` 合成真人小圆/字幕/音效/响度。这条路线不需要 npm 和 React，镜头、场景底、转场、音效都已内置，照 README 逐步执行即可。
- **Remotion**：按 [remotion.md](remotion.md) 先准备副本和字幕数据，再接入连续播放的真人视频、独立字幕层和按时间启动的动画场景。动画场景用主库 `update(t01, P)` 逐帧驱动（移植方法见 studio.md）；镜头推进用 [camera.md](camera.md)；图标动效与文书转场用 [remotion/](../remotion/README.md) 组件。

用户指定其他工具时，用相同时间轴原则适配，不强制更换框架，但 SKILL.md §0.5（数字呈现）、§0.6（动感最低要求）与 §0.7（声音三层）在任何路线下都必须满足。

**声音三层（v0.6，任何路线必做，[sound.md](sound.md)）**：`make_sfx.py` 生成音效、`make_bgm.py` 按章节 mood 生成 BGM（或用户授权音乐）、`mix_sound.py` 把口播+BGM+音效混成 `mixed.wav`（自动 ducking：间隙 −7dB / 说话 −17dB），合成脚本音轨用 `mixed.wav`。自建引擎也必须产出 events.json（至少每镜头边界一个 whoosh）并走这条链；只 map 原声 = 不合格。BGM 默认必加，仅用户明确不要音乐才省略并声明。

实现每个镜头时：

- 由当前帧确定画面：按工程实际 fps 把时间转换为帧（`Math.round(秒数 * fps)`）；镜头内局部帧 = 当前帧 − 镜头起始帧。**同一段动作统一使用一种时间基准**，全局帧与局部帧不混用。
- **数字镜头**（SKILL.md §0.5）：count-up ≤ 0.6s 且精确停在稿件值，停稳后停留 ≥ 1.2s；合计数字一次性显示，不做实时累加；镜头推近后停留（pipeline `camera: 'hold'`），焦点对准数字。
- 交接动作先决定唯一道具由谁持有、从哪只手到哪只手，接触后由接收方接住；不要用两份相同道具替代转移（主库交接工厂已内置此逻辑）。
- 分层构图：远景、人物道具、前景；**字幕、头像和真人窗口放在独立于运动场景的稳定图层**。缩放/移动时检查运动开始、中间、结束处是否越界或遮挡。
- 转场沿用前一镜头道具的最后位置、比例和朝向作为后一镜头起点；不要对所有镜头套同样的淡入、放大、扫光。

对原稿口误、缺字、错别字不默默修改法律含义；重要数字、结论和案例事实先核对来源与口径。音乐和音效应有使用权限（程序化生成天然无版权），音量不压过口播；BGM 默认必加，仅用户明确不要音乐才省略并声明（sound.md）。用户只要求修改局部时保留其他部分，只重新验收受影响部分和成片播放。

**这一步应得到：** 包含所有镜头、真人画面、字幕与音轨的可编辑项目，以及覆盖完整时长的成片 MP4。

## 六、验收后交付

对实际导出的 MP4 执行 [delivery-qa.md](delivery-qa.md)：文件可播放、时长与分辨率、原声完整且未重叠、字幕与原稿及时间一致；看全片关键帧与转场，连续播放动作段。机器检测可辅助找黑帧、静音和时长错误，不能替代实际看与听。

交付时给出可播放的成片路径和可编辑项目路径，说明时长、画幅、主要处理以及真正完成的检查。缺少工具、无法访问素材、没有听看或某项质量仍未解决时具体说明限制；不要用"全部通过"掩盖未做的检查。
